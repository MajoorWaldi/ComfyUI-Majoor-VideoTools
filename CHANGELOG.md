# Changelog

## Unreleased

- Edit Mode: three named presets (`Image to Reel`, `Remix`, `Music Edit`; `Advanced` leaves the five modes to the `mode` combo) and a `style` (the editing profile of the planner and of the music, `Mode default` keeps the one of the mode skill). A preset sets the mode, the mode sets the preset back; `/majoor/modes` also gives the presets. The two widgets come first: a controller saved before them is read with its values shifted to the widgets they belong to and shows `Advanced`.
- Check before a run: when a graph has an Edit Mode, queueing it first names the nodes the frontend does not know and asks the Ollama of this machine (`/majoor/preflight`, only localhost) whether it answers and has the model of each Ollama node that runs (`ollama pull <model>`), and stops with that message in place of a Python trace. If the check itself fails the run goes on.
- Audit of the skills: a plan of an LLM is no longer refused for a `color` that is not one (`none`, `transparent`: the color of a shot only codes the timeline, the color of a text falls back to white, a background is dropped) nor for an `aspect_ratio` that the engine does not have (`2.39:1`: the one of the node is used), both seen in runs of gemma4 and qwen3.8 on the planner; a test checks that the transitions that every skill teaches are the ones the engine renders; stale mentions cleaned in the skills. Measured on 3 briefs with an EDIT RHYTHM of 6 shots: the planner gives valid JSON with the right ids and cuts on gemma4 (15 to 22 s) and qwen3.8 (2 to 4 minutes), adding a block of 8 rules at the top did not help.
- Prompt enhancer: skill `prompt_enhancer` (the few words of the user, the pictures and the frames of the videos become a richer, creative brief: the subject as the pictures show it, a hook, signature moments, camera, light, texture and sound, never what the user did not ask for); each mode skill has an `enhancer:` line (what the mode asks of it) that a node tagged `"enhancer": true` receives as `extra_instructions` when the mode changes. In SECATOR_engine_v8 the enhancer reads REFS in every mode but the text one, `<Video 1>` (the rhythm video in the reference mode, the video to modify in the remix) and `<Video 2>` (the motion video) through Edit Skills, with a vision model of its own. Measured: qwen3.8 reads the details of a picture and of the frames (hair, outfit, the place) and keeps the remix faithful, gemma4 reads far less and invents.
- Automation by mode and profile: the mode skills say whether the reference video is used (`reference_video`, Edit Mode sets its toggle: on for the reference and the remix); a music skill gets the music direction of the profile (`music:` of the profile files: phonk for Viral / Aura Farming, soft piano for Beauty / Premium...) and the density of the cuts; a node tagged `"profile": true` takes the profile of the mode (the music of the edit). The H3 recipes name the videos by what they give: `MOTION_VIDEO`, `MOTION_VIDEO_FRAMES`, `MOTION_VIDEO_SAMPLE` (the motion and camera reference of H3 and the LLM, was `REF_VIDEO`) and `REMIX_MASK` (was `MASK`), blue / orange / red loaders for the rhythm, motion and remix videos; the sample of frames for the LLM is every 12th frame, 24 at most, for videos of up to 30 s; the LLM of the recipes stays loaded 2 minutes after a call.
- Deploy Shots: `max_shots` linked through a Get / Set pair or a switch (the one that EDIT MODE sets) reads the count of the node it ends at, so a count that follows the shot list (Create Timeline, or Scene Detect in the remix) works.
- Deploy Shots: the first reference picture is named REF in the older recipes and graphs and REF1 in the new H3 recipes; a block that read REF1 in a graph that sets REF (or the reverse) left H3's `ref_image_0` and the LLM without the picture, silently, the report only warned. The Get nodes of the blocks now follow the Set node that exists (the report says so), and the warning for a missing REF / REF1 says that the first picture then reaches neither H3 nor the LLM.
- `shot_count` output (the number of shots) on Create Timeline, Scene Detect & Split and Cut Markers; `max_shots` of Deploy Shots can be linked to it (or to any number): linked to a source node it deploys every shot it lists, linked to a number it deploys that many. The recipes carry the new output slot.
- MiniMax Music 3 (native in ComfyUI): skill `music_brief_minimax3` (the three-part caption, section-tagged lyrics, tempo, length and sfx of the edit, sting to song). Measured: it fills exactly the length asked (5 s -> 4.99 s, 8 s -> 8.00 s, 12 s -> 11.99 s, no silent tail, 6 to 22 s of compute), so a short edit needs no padding, but it follows the tempo loosely (8 s takes: 90 BPM asked -> 94-95; 150 -> 150 or 122; 128 -> 90 to 124, a phonk stays near 100).
- Short music (5 to 8 s): `music_brief_from_plan` gets a rule for a sting or a cue (one idea, no build-up or outro, a hit on the first beat, four descriptors, one mood, 90 to 130 BPM) and no longer writes the tempo in the tags (ACE-Step has its own field). Measured on ACE-Step 1.5 turbo: it keeps the requested length but ends a short piece early (5 s asked: the sound stops at 3.1 s; 8 s asked: at 7.1 s; 12 s asked: at about 7.5 s), so the music workflow asks for `max(10, a * max(1, 3 - a / 8))` seconds (8 s -> 16 s, 24 s -> 24 s) and trims to the length of the edit: 4 of 4 takes of 8 s keep their sound to the cut.
- Transitions: `fade_white`, `glitch` (RGB split and noise), `shake`, `strobe` and `invert` join flash, flash_black, fade_black, whip, whip_v, blur and punch; the names an LLM writes (`flash_white`, `cross_dissolve`, `rgb_split`, `camera_shake`...) are understood, and a name that no transition has is a plain cut instead of stopping the workflow with `unknown transition 'flash_white'`. The skills `timeline_planner`, `dynamic_edit_skill` and `h3_shot_prompt_from_plan` know them.
- Skills `h3_shot_prompt_from_plan` v2.0 and `remix_edit_director`: the prompt follows the full-reference guide of MiniMax H3 (`VIDEO_PROMPT_WRITING_GUIDE_ref_en`): six sections (`subject_definitions`, `summary` with its task tag, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music`), `<Subject N>` for what the pictures show, `[Shot 1]` without a timestamp and later shots `At 00:SS.mmm`, the camera words of the guide (small/large amplitude, slow/fast speed), `[video editing]` + `The target video is an edited version of <Video 1>` for the remix. The old format was the single-image (I2VA) one, whose line says that `<Picture 1>` is the first frame at 0.00 s.
- H3 recipes `Remix Mode Minimax H3` and `Text Audio & Refs Mode Minimax H3`, audit: the prompt writer never saw the frames (the side chats of the shot analysis only passed `meta`, which carries the connection, not their answer): one chat now reads the pictures, the frames of the shot and of the reference video, announced by the user message of Edit Skills; Edit Skills takes `video_1` / `video_2` (frames) and outputs `images` (pictures then frames of each video on one canvas) and the VIDEOS block of its user message (`<Video 1> = images 3 to 10 of this chat...`); skill `h3_shot_prompt_from_plan` v1.2 reads the VIDEOS block, names every listed `<Video k>` in the prompt and never writes one that is not listed; in the text recipe H3's `<Video 1>` is the reference video (it was the frames of the placeholder card), optional through the `reference_video` toggle of Edit Mode (or a bypass of the three nodes tagged for it); in both recipes H3 `ref_video_1` was wired to a duplicate input and never received the reference video.
- Deploy Shots: a recipe whose name has an `&` (`Text Audio & Refs Mode...`) is accepted.
- Select Shot: `frame_sampling = every_n` with `every_n` and `spread_to_end` (sample_count is the most frames kept), the same sampling as Select Every N Frames: the last frame of the shot is kept and the frames are thinned evenly from the first to the last. The new widgets come last, saved workflows keep their values.
- Select Every N Frames: keeps frame 0, N, 2N... of an IMAGE batch, at most `max_frames`; with `spread_to_end` the last frame is always kept and the frames are thinned evenly from the first to the last (16 pictures that cover a whole clip for an LLM), without it the first `max_frames` stop before the end. Outputs the batch and the kept `frame_indices` as text.
- Effects of a plan: a value out of range (zoom 0.8, speed 12, focus 1.3, opacity 2...) is brought to the nearest accepted value instead of stopping the whole workflow with `zoom must be between 1 and 4` (an LLM writes a pull-out as a zoom under 1); a wrong `refs` picture number and a value that is not a number are still errors.
- Scene Detect & Split: `rhythm_text` and `skeleton_json` outputs, the detected shots as a rhythm skeleton (cuts too short for a shot are grouped as sub-cuts) for the LLM and for Create Timeline (`skeleton_json`).
- YuE2 (song model) music: skill `music_brief_yue2` (style as tags, lyrics with section tags, tempo, length and sfx of the edit, short clip to long edit); Music Brief gets a `lyrics` output cut to one line per 6 s of the edit and one more, and the tempo written in the style (`128 BPM`) follows the node's bpm. Measured on YuE2 (the song is as long as `max_duration`, which is a cap: it stops by itself only at the end of its sections, about 20 to 25 s each; a line is sung in 4 to 6 s; the `BPM` tag and the steady-kick phrase of Music Brief hold the tempo within 1 BPM, a bare tag within about 10).
- Audit of the nodes: a cropped VIDEO (Load Video Advanced, Crop Video) given to Scene Detect & Split, Select / Apply Shot Metadata, Cut Markers or the previews was read from its uncropped file, the crop is now rendered; a plan is refused with a clear message instead of hanging or crashing ffmpeg when it has more than 150 shots (Windows refuses the placeholder command: `WinError 206` at about 190), lasts more than an hour, or has an fps outside 1 to 240, a resolution outside 64 to 4096, or a non-numeric fps or resolution; the BPM in the rhythm text of a music is rounded (it read 120.08999633789062).
- Load Video Advanced (audit): the start written by the trim bar is floored to the millisecond (rounded up it skipped the first frame: 0.667 s gave frame 17 for frame 16); a start after the end or a selection of no frame is an error (it gave an empty batch); a selection of every frame in order keeps the video and its audio; up to 64 frames of a long clip are read one by one (a 30 s 1080p clip with `~8`: 0.9 s and +0.2 GB instead of 18 GB); the file is checked to be in the input, output or temp folder at load, and a bad name gives an error instead of an exception in the route, which probes without blocking the server; a crop or a start made for another file is reset when the file changes.
- `tests/comfy/`: checks that run with ComfyUI's python (`check_schemas.py`: every node builds its schema; `check_nodes.py`: every node on real media with its refusals; `check_load_video_advanced.py`: trim, crop, selection, sparse reading, refusals, memory).
- Remix: the instruction of Edit Mode now reaches the LLM (the blocks read their edit request through a link, which overrode the value written into their widget). A remix LLM stage (`remix_planner` skill) looks at the reference pictures and 8 frames of the video (Load Video Advanced `frames = ~8`) and writes the edit request that every block receives; Deploy Shots reuses a node of the graph that has the title of the recipe's shared node and gives the same kind of value.
- Pose ControlNet: Edit Mode switches it per mode: in the remix `pose_strength` (off with `pose_control`), in the other modes strength 0, which H3 skips; applied on a change of mode and after Create shots. The plan recipes keep their ControlNet node bypassed, the shots being placeholder cards.
- Load Video Advanced: `~n` in `frames` keeps n frames spread evenly.
- Profiles and modes are skills: `profile_<id>.md` (header: length and the five dials; text: rhythm, camera, art direction) and `mode_<name>.md` (header: profile, genre, reference_mode of the planner; text: its instructions; the remix: `pose_strength` and the replacement instruction), edited like any skill and read again at every use (`/majoor/modes`). The `skill` widget of Edit Skills lists only system prompts; Reload skills refreshes the profiles too.
- Remix: the shot analyzer and the edit director of the video recipes are now skills (`remix_shot_analyzer`, `remix_edit_director`) run by Edit Skills nodes in the recipes.
- Edit Mode: up to five reference pictures (`reference_2` to `reference_5`); in remix mode `pose_strength` (the pose ControlNet of H3, driven by the pose of the original shot) and `remix_instruction` are written into every shot block, also right after Create shots; the planner takes the profile, genre, `reference_mode` and instructions of the mode when the mode changes (`core/modes.py`). The recipes carry REF2 to REF5 (`ref_image_1` to `ref_image_4` of H3) and the director prompt of the video recipe knows them and the pose map.
- Edit Mode: one node for the whole graph. Its `mode` (image, reference video, music, text, remix) and the toggles `reference_2` / `reference_3` enable or bypass the nodes that carry a `properties.majoor_mode` tag, and set the rhythm source and the shot list switch. Applied on a change and when the graph is queued (`web/majoor_mode.js`).
- Several references: Edit Skills takes an `images` batch and counts the pictures from it; the three recipes get REF2 and REF3 (second and third reference picture of H3) and REFS (the batch the LLM reads); the planner and the H3 writer skills name `<Picture 2>`, `<Picture 3>` for the shots that show them.
- Audio Rhythm: `music` is optional. Without music it gives the plain rhythm text of the plan, and with an empty plan an empty text, so it can stay in every graph.
- Deploy Shots: a `ComfySwitchNode` between a Create Timeline and a Scene Detect & Split is followed (the input its `switch` selects), so one switch chooses the shot list of a whole graph; `recipe = auto` then takes the plan or the video recipe by itself.
- Edit Skills: a `profile` (Viral / Aura Farming, Beauty / Premium, Narrative / Cinematic, Product / Advertising, Music Video) and five dials (`cut_density`, `transition_intensity`, `creative_freedom`, `reference_fidelity`, `narrative_coherence`; `auto` keeps the profile's value). The profile is a starting strategy added to the system prompt, never a restriction: the brief wins. Music skills ignore it. The new widgets come last, so saved workflows keep their values.
- Apply Shot Metadata: a take is now added to the takes already stored for the project, not to the (possibly cached) list it receives. Regenerating one shot of a chain used to give it `take_001` again and drop the other takes; it now gives `take_002` and keeps the rest.
- Skills: the LLM now writes a `character` line from what it sees in Picture 1 and reuses it in every prompt; the examples of `timeline_planner`, `h3_shot_prompt_from_plan` and `dynamic_edit_skill` are marked as another person, so their look (hair, clothes) is no longer copied into the prompts.
- Music Brief: reads the JSON of the `music_brief_from_plan` skill and outputs `music_prompt` (with tags for a steady beat), `bpm`, `duration` and `sfx_json`, to wire an LLM to ACE-Step; `bpm` and `duration` can replace the brief's.
- Shot Assemble: click a shot of its timeline, then Regenerate: the seed of that shot's generation block (the nodes Deploy Shots stamped with the shot id, or those downstream of its Select Shot) changes and the graph is queued; ComfyUI's cache means only that shot is generated again.
- Audio Rhythm: finds the kicks, snares and hi-hats of a music (spectral flux per frequency band) and adds, under each shot of the `rhythm_text`, the hits, the loudness and what they are good for (cuts on kick/snare, only effects on the hi-hat). Output `hits_json` has the times per band.
- Load Video Advanced: loads a video file with trim (`start_time`, `duration`), crop (`crop_x/y/width/height`) and a `frames` selection (`0-10, 24, 30-90:5, -1`). Outputs `video`, `images` (IMAGE batch) and `frame_indices` (list of INT). The node shows the video with a draggable crop box, a trim bar and an Add frame button; route `/majoor/video_info`.
- Shot Assemble: optional `music` and `sfx` audio inputs (with `music_volume`, `sfx_volume`, `music_fade`), mixed over the audio chosen by `audio_policy` (with `mute` they are the only audio), cut or padded to the length of the edit, with a fade out at the end of the music.
- Edit Skills: a node that loads a skill (a system prompt kept in `skills/`), switches its parts on or off (overlays and split screens, text, reference mode, genre), fills in the length, fps and aspect ratio, and outputs the `system_prompt`, the `user_message` (brief, pictures, rhythm) and an `info` line. Reload skills and Copy prompt buttons; routes `/majoor/skills` and `/majoor/skills/compose`. Skills shipped: `dynamic_edit_skill`, `timeline_planner`, `h3_shot_prompt_from_plan`, `music_brief_from_plan` (kind `music_writer`: the rhythm and effects of an edit become a brief for a music model, BPM, structure, moments and the sound effects of the transitions).
- Overlays (surimpression, picture in picture) and split screens (`overlay`, `split`, `refs` in a plan), rendered by Shot Assemble from the takes of the shots; `examples/prompts/dynamic_edit_skill.txt`, the general skill prompt for a vision-language model (brief, pictures, reference frames), with `examples/dynamic_edit_product_ad.json`.
- Deploy Shots: new recipe `Minimax H3 TimelineShot Creator` (from the working AutoEdit workflow); the blocks read the shot list straight from Create Timeline / Scene Detect & Split; recipes declare their kind and priority (`extra.majoor_recipe`) for `auto`; block name read from the Set/Get names, nested groups and Reroutes handled.
- Create Timeline: `card_text` option (on by default) writes the brief of each shot on its placeholder card, wrapped and shrunk so that no text is ever cut off.
- Prompts keep the role, the cuts and the transitions of a shot and drop negations ("no cuts", "no text", "one continuous take"): planner prompt, new `h3_shot_prompt_from_plan.txt`, and a guard in Create Timeline.
- Select Shot: `fx_json` and `rhythm_text` outputs (transition, cuts and effects of the shot), shown in its preview.
- Cut Markers: a node with a timeline editor (waveform, beats, cuts of the video, markers placed by hand, snapping, fill from beats or video cuts, undo) that outputs a rhythm skeleton for Create Timeline.
- Create Timeline: `skeleton_json` (rhythm of a music or a video, prompts and effects of an LLM), `source = none`, `cut_snap` for `source = video`. Select Shot: `generation_seconds` output. Shot Assemble: `effects` and `sub_cuts` toggles. Deploy Shots: `recipe = auto`, a noise seed per shot, and the `minimax_h3_ref2va_plan` recipe for shots written in a plan.
- Deploy Shots: a node with a Create shots button that adds one block per shot from a recipe (`recipes/`, `minimax_h3_ref2va` included), chains the Apply Shot Metadata nodes and connects Shot Assemble.
- Timeline from JSON is now **Create Timeline** (node id `MajoorCreateTimeline`) with sources json, music (cuts on bars/beats) and video (rhythm of a reference), and the outputs `plan_json` and `rhythm_text`.
- Create Timeline: per-shot effects (`sub_cuts`, `speed`, `speed_ramp`, `zoom`/`focus`, `flip`, `look`, `transition`, `text`) rendered by Shot Assemble; `cut_snap = half_beat`; new planner system prompt for dense, dynamic edits.
